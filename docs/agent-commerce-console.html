في 13 نوفمبر 2026 أطلقت OpenAI محفظة ChatGPT Wallet (بشراكة American Express وMastercard وVisa): الوكيل يدفع باعتماد دفع مُرمَّز، وكل عملية شراء تمر بمراجعة وتحقق أمني من المستخدم، وOpenAI نفسها سمّت التفويض المسبق ضمن حدود الإنفاق والفئات والفترات عملًا مستقبليًا. السؤال المفتوح في كل هذه المنظومة: «هل التنفيذ مطابقٌ لما وافق عليه المستخدم — ومن يستطيع إثبات ذلك لاحقًا وباستقلال؟» الترميز يحمي بيانات البطاقة؛ لكنه لا يربط التنفيذ بالتفويض. هذه الوحدة هي طبقة الربط هذه — ملتزمة هنا بالكامل، تعمل دون اتصال، ويعيد أي طرف اشتقاق إثباتها.

The moment, answered

OpenAI launched ChatGPT Wallet (2026-11-13, with American Express, Mastercard, Visa): agents pay with tokenized credentials, every purchase passes a user review + security check, and pre-approved delegation within spending/category/time limits is named as future work. The open question everywhere: "did the executed order match what the user approved — and who can prove it later, independently?" Tokenization protects card data; it does not bind execution to authorization. This console is that binding layer — committed here, running offline, re-derivable by anyone.

The arc, measured — not designed

Run node examples/agent-commerce-security-suite/run.mjs: zero keys, no network (loopback only), synthetic orders, exit 0 only on the exact arc. The numbers above come from the committed deterministic artifacts.json: CONSENT VERIFIED → EXECUTE exact VERIFIED → 8/8 attacks INVALID with the named class (total drift · merchant swap · injected item · credential substitution · expired authorization · single-use replay · record tamper · malformed payload) → real MCP server rejects a drifted order → real REST API verifies the exact order.

Five products, their real statuses

1 · Agent Authorization Firewall — BUILT · TEST_EXECUTED (offline). 2 · Verifiable Consent Receipts (CGCR/1) — BUILT · TEST_EXECUTED. 3 · Agent Risk Engine (AGR/1) — BUILT · TEST_EXECUTED (deterministic taxonomy, never a fraud score). 4 · Agent Commerce SDK + MCP + REST API — BUILT · TEST_EXECUTED; npm publication is owner-gated. 5 · Cross-Chain Execution Attestation — BUILT · TEST_EXECUTED as the offline attestation surface CGXA/1 (the adapter registry is pinned to committed chain facts: Core DAO anchors live on chainId 1116, LIVE/RECORDED; Stellar anchor contract per the evidence matrix; the on-chain broadcast legs are OWNER-GATED / NOT_PERFORMED and no broadcast surface exists in the module; carrying the binding into the Soroban lane is integration NOT_BUILT).

Boundaries (standing)

Execution verification never decides delivery conformity (DDE/1) · VERIFIED ≠ SAFE · the AGR/1 taxonomy is deterministic — never a probabilistic fraud score · the actor is declared, never detected · durable single-use anchoring is NOT_BUILT (consumption is process-local by design) · no contact, integration or endorsement is claimed with OpenAI, American Express, Mastercard, Visa or any provider · every order is synthetic (the credential is a placeholder, never a PAN) · funding stands at $0.
