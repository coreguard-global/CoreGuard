# 0.1.3 — MCP reliability and adoption (release candidate, NOT RELEASED)

Status: **prepared on `main`, not published.** npm still serves `0.1.2`, and the
package manifest on `main` still says `0.1.2`. That is deliberate: the version
bump lands in the same commit as the publish, so no README, listing, registry
entry or badge in this repository can ever advertise a version npm does not
serve. Publishing is owner-gated (`docs/owner-execution/NPM-PUBLISH-READINESS-AND-STEPS.md`).

Theme: this release is not "more tools". It is the four existing tools made
inspectable, validated and impossible to drift — because the marketplace page for
0.1.2 showed the schemas as unread and no runtime detail, which is a
distribution defect even when the code is fine.

## What changed on `main` for 0.1.3

| Change | Why | Acceptance |
|---|---|---|
| `serverInfo.version` reads `package.json` | the server answered `1.0.0` while npm served `0.1.2` — a real mismatch | `serverInfo.version === package.json.version`, asserted in CI |
| `outputSchema` on all four tools | a client can render results without reading this repository; the listing showed inputs only | every tool has `outputSchema.type === "object"` and a description, asserted in CI |
| `structuredContent` on every result | machine-readable results, with the text content kept for older clients | `structuredContent` deep-equals the parsed text content |
| Input validation (`MISSING_ARGUMENT`, `INVALID_ARGUMENT`) | unclear failures were indistinguishable from server crashes; `nowSeconds` accepted a number | one test per class; `ping` still answers after each failure |
| Stable error contract (`CODE: detail` + `{code, detail}`) | an agent can branch on the code instead of parsing prose | exported `ERROR_CODES`; asserted in CI |
| `selfCheck` covers the version, schemas and error contract | the server's own gates now fail on the defects above | `selfCheck()` all true |
| Runnable example `examples/agent-commerce-mcp/run.mjs` | a developer can see approve → refuse → verify in one command, offline | `PASS (8/8)` on a clean clone, no install |
| `docs/agent-commerce-mcp-compatibility.md` | clients are listed with an explicit CONFIG-DOCUMENTED / RUN-BY-HAND vocabulary | no client is called tested while the run log is empty |
| `docs/agent-commerce-mcp-security.md` | what the surface guarantees and, more importantly, what it does not | includes process-local replay and caller-supplied trace |
| Package README: per-tool reference, errors, client configs | the listing cannot show parameter detail; the package page can | every tool's inputs, outputs and failures documented |

## Test evidence

The MCP contract test now runs 11 tests against a **real spawned stdio child**:
initialize, tools/list, authorize, exact verify (`VERIFIED`), drifted verify
(`INVALID` + named class), unknown tool, unknown method, non-JSON line,
`selfCheck`, version equality, and schema/structured-content coverage. The
example script prints `PASS (8/8)` and exits non-zero on any failure.

## Deliberately NOT in 0.1.3

- **Ten tools.** The engine already has the capability; adding `create_intent`,
  `check_limits`, `revoke_consent`, `audit_transaction` as separate MCP tools
  would duplicate SDK functions and multiply schema surface before any client
  asked for it. The four tools stay; the roadmap question is "which one call is
  missing for a real integrator", not "how do we reach ten".
- **Durable single-use replay protection.** Still `NOT_BUILT`; the ledger is
  process-local and every description says so.
- **A store/payment integration.** No merchant, PSP or wallet is contacted by
  this package. Those are adapters, not this release.
- **A security grade.** We do not chase a marketplace letter. We cite the
  threat model page instead.

## Publish checklist (owner)

1. `npm run publish:check` and the full test lane green on the commit to publish.
2. Bump `package.json` to `0.1.3` and `packages/agent-commerce/server.json` in the
   same commit; the CI version test enforces the pair.
3. Publish to npm; verify `npx -y @coreguard/agent-commerce@0.1.3` answers
   `initialize` with `serverInfo.version === "0.1.3"`.
4. Update the MCP Registry entry and the marketplace listing with this page's
   contents; never edit the listing ahead of npm.
5. Record the date, tarball integrity and the four tool names in
   `docs/agent-commerce-mcp-compatibility.md` run log if a client was launched.
