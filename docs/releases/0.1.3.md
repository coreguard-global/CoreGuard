# 0.1.3 — MCP reliability and adoption (release candidate, NOT RELEASED)

Status: **prepared on `main`, not published.** npm still serves `0.1.2`, and the
package manifest on `main` still says `0.1.2`. That is deliberate: the version
bump lands in the same commit as the publish, so no README, listing, registry
entry or badge in this repository can ever advertise a version npm does not
serve. Publishing is owner-gated.

**Readiness checklist:** `docs/releases/0.1.3-publish-readiness.md`  
**Security boundaries:** `docs/agent-commerce-mcp-security.md`  
**Client compatibility/run log:** `docs/agent-commerce-mcp-compatibility.md`

Theme: this release is not "more tools". It is the four existing tools made
inspectable, validated and impossible to drift.

## What changed for 0.1.3

| Change | Why | Acceptance |
|---|---|---|
| `serverInfo.version` reads `package.json` | server/npm drift is a release defect | `serverInfo.version === package.json.version`, asserted in CI |
| `outputSchema` on all ten tools | clients/inspectors need machine-readable result shape | every tool has `outputSchema.type === "object"` and description, asserted in CI |
| `structuredContent` on every result | machine-readable results, text kept for older clients | covered by tests/smoke |
| Input validation (`MISSING_ARGUMENT`, `INVALID_ARGUMENT`) | bad inputs must fail clearly and safely | stable error contract, server survives |
| Stable error contract (`CODE: detail` + `{code, detail}`) | agents can branch on code | exported `ERROR_CODES` |
| `selfCheck` covers version/schemas/error contract | server self-gates against drift | `selfCheck()` green |
| Runnable demo `examples/agent-commerce-mcp/run.mjs` | approve → refuse → verify, offline | exits non-zero on failure |
| Runtime smoke script `scripts/agent-commerce-mcp-smoke.mjs` | real stdio runtime proof for publish/MCPRush readiness | `11/11 PASS` offline |
| Compatibility matrix | explicit CONFIG-DOCUMENTED / RUN-BY-HAND / CI-SMOKE vocabulary | no fake "Tested" claims |
| Security model doc | what is guaranteed and what is not | includes process-local replay boundary |

## Test / verification evidence

- MCP contract tests (real spawned stdio child): `node --test test/integrations/agent-commerce-mcp.test.mjs` (**17/17 PASS** on this dev branch).
- Runtime smoke: `node scripts/agent-commerce-mcp-smoke.mjs` (**11/11 PASS**).
- Example: `node examples/agent-commerce-mcp/run.mjs` (**8/8 PASS**).

## Deliberately NOT in 0.1.3

- **Distributed/device-synced consumption ledger / HA consensus.** `NOT_BUILT`; process-local and AC-CS/1 file-backed host store are available with honest boundaries.
- **Live store/payment/wallet/PSP integration.** No external commerce/payment network contacted.
- **Security grade as marketing guarantee.** Cite threat model and evidence, not letter grades.

## Publish checklist (owner)

1. Green CI on publish commit + smoke/contract tests pass.
2. Bump `packages/agent-commerce/package.json` and `packages/agent-commerce/server.json` to `0.1.3` in the **same commit** as publish.
3. Publish to npm; verify clean install: `npx -y @coreguard/agent-commerce@0.1.3`.
4. Confirm `initialize` reports `serverInfo.version == "0.1.3"` and `tools/list` exposes 10 tools with schemas.
5. Update MCPRush listing/registry metadata, request runtime scan, add demo/release notes links.
6. Record RUN-BY-HAND evidence in `docs/agent-commerce-mcp-compatibility.md` (Claude Code first).

## Honest boundaries (must remain visible)

- `VERIFIED ≠ SAFE`.
- No external commerce platform/payment network contact.
- Single-use consumption is process-local (durable anchoring `NOT_BUILT`).
- Execution trace is caller-supplied observed data; this package verifies consistency, not external truth of all real-world systems.
