# 0.1.4 — the tool surface the server actually exposes

**Status:** prepared in this repository; published by the gated release workflow (`workflow_dispatch`, `NPM_TOKEN`, `scripts/release-please.mjs`). If you are reading this before the workflow ran, the paragraph is a plan, not a record.

## What changed

`0.1.3` shipped a package whose `server.json` said **10 MCP tools** while the server it contains exposes **26**. That was not a code change waiting to happen — it was a manifest and description that never caught up with the Wave 1 and Wave 2 tools. Two consequences, both visible:

- directories that scan the published package (MCPRush among them) show a tenth of the surface;
- the paste-ready tool reference could not be generated at all, because 16 tools had no executed example.

`0.1.4` fixes both:

- `server.json`: version `0.1.4`, description names 26 tools, package version follows.
- `package.json`: version `0.1.4`, description names 26 tools.
- `scripts/mcprush-tool-reference.mjs`: executed example argument sets for all 26 tools, including the CGCP/1 mappings against a seeded, file-backed control plane. The page now regenerates deterministically and `--check` is a real gate.
- `docs/mcprush/tool-reference.md`: regenerated — 26 sections, every example executed against the shipped server.

No tool behaviour, schema or outcome changed. A caller on `0.1.3` gets the same results from the ten tools it could discover; `0.1.4` makes the other sixteen discoverable.

## Boundary

An offline, deterministic verification engine. `VERIFIED` means the executed bytes matched the approved bytes — not that the purchase was safe, not that a provider settled anything, not that a device exists. No payment custody, no broadcast, no network calls, no keys, no wall clock inside a commitment. `VERIFIED ≠ SAFE`, and the control-plane tools say `NOT_BUILT` about multi-tenant RBAC/SSO, distributed HA, KMS/HSM and managed SLAs rather than implying them.
