# MCPRush Conversion Strategy (honest, evidence-first)

**Status:** strategy doc only. No external MCPRush edits performed by this change.

## Positioning

CoreGuard Agent Commerce MCP is a fail-closed verification/evidence layer for agentic commerce.  
Do not claim: secure-by-grade, fraud-proof, endorsements, or customer traction.

## Funnel

1. **Discovery (MCPRush/GitHub/npm):** clear description, 10 tools, schema visibility, security/threat model link.
2. **Trust:** runtime smoke evidence, CI contract tests, demo 60s (success + refusal), honest boundaries (`VERIFIED ≠ SAFE`, process-local/file-backed-host consumption).
3. **Activation:** `npx -y @coreguard/agent-commerce` + client config + demo run in < 5 min.
4. **Conversion:** pilot/integration inquiry for policy management, reporting, custom adapters, or control-plane deployment.

## MCPRush actions (owner, post-publish)

- Update version/metadata after npm publish.
- Ensure tool schemas/params visible; if not, provide runtime evidence to support.
- Request runtime security scan on live MCP server.
- Add links: release notes, security model, compatibility run log, 60s demo.
- Track: listing views/installs where available, GitHub stars/issues, npm downloads, pilot inquiries. **Do not equate downloads with active users/customers.**

## CTA

- OSS: install and test locally.
- Design partner/pilot: bring sanitized sandbox/payment/trace samples; CoreGuard provides verification/evidence integration scope (SOW-bounded).
